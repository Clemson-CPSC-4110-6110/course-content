Part 1 — What Is a Shader?

The question we're answering

When Unity draws a triangle, how does it decide the color of every pixel inside that triangle?

Answer: a shader — a tiny program that runs on the GPU, once per vertex and once per pixel.

Shaders run on the GPU, not the CPU

CPU

A few powerful cores. Runs C# game logic sequentially. Bad at doing the same math on millions of pixels.

GPU

Thousands of tiny cores. Runs the same small program in parallel on every vertex and every pixel. Brilliant at graphics.

A shader is literally a program designed for that parallel model.

Vertex shader vs. fragment shader

  • Vertex shader — runs once per vertex. Job: decide where each corner of a triangle lands on screen. Can also push vertices around for animation.
  • Fragment (pixel) shader — runs once per pixel the triangle covers. Job: decide what color that pixel is.
  • In Shader Graph these correspond to the Vertex and Fragment blocks of the Master Stack.

Only the purple boxes are programmable. That's what you write when you "write a shader."

Why shaders feel like magic

Every visual effect you've ever seen in a game is a shader doing math on pixel coordinates: fire, water, holograms, outlines, dissolves, cartoon shading, X-ray vision.

There is no fire. There is only math that outputs orange.

Part 2 — Why Shader Graph?

The traditional way: HLSL code

half4 frag(Varyings IN) : SV_Target
{
    half4 col = tex2D(_MainTex, IN.uv);
    half rim = 1 - saturate(dot(IN.normal, IN.viewDir));
    col.rgb += rim * _RimColor.rgb;
    return col;
}

Powerful, but: new syntax, platform quirks, no preview, easy to crash your GPU.

Shader Graph: the visual alternative

  • Drag-and-drop nodes instead of typing HLSL
  • Live preview at every single node — you see exactly what each step produces
  • URP/HDRP-aware — handles lighting, shadows, fog, and XR for you
  • Same underlying code — Unity compiles your graph to HLSL at build time

Tradeoff: easier to learn, slightly less flexible than hand-written HLSL. For 95% of VR effects you will never hit the ceiling.

Requirements for this tutorial

1
Unity 2022.3 LTS or newer
2
A project using the Universal Render Pipeline (URP) — the 3D (URP) template works
3
Shader Graph package (installed with URP by default)
4
A sphere in the scene to test on

Shader Graph does not work with Unity's legacy Built-in pipeline.

Part 3 — The Shader Graph UI

Creating your first graph

1
Right-click in Project → Create → Shader Graph → URP → Lit Shader Graph
2
Name it SG_MyFirstShader (naming convention: prefix with SG_)
3
Double-click to open the Shader Graph editor window
4
Right-click in Project → Create → Material, drag your graph onto the material's Shader slot, then assign material to a sphere

Lit vs. Unlit: Lit responds to scene lights and shadows (PBR). Unlit ignores lighting and draws raw color — good for holograms, UI, skyboxes.

Anatomy of the editor

  • Blackboard (left) — properties exposed to the material inspector (color, sliders, textures)
  • Graph Inspector (right) — graph-wide settings (surface type, blend mode, cull mode)
  • Main Preview (bottom-right) — a sphere showing the final result in real time
  • Master Stack (center-right) — the final output, split into Vertex and Fragment blocks
  • Node canvas (everywhere else) — where you drop nodes and wire them together

The Master Stack

Vertex
• Position • Normal • Tangent
Fragment
• Base Color • Metallic • Smoothness • Normal (TS) • Emission • Alpha

Whatever wires into these ports becomes the shader's output. Everything else in the graph exists only to compute these values.

Part 4 — Nodes, Wires, and Data Types

Every node is a function

A node takes inputs on the left, does math, produces outputs on the right.

Multiply
in A (float) in B (float) → out (float)
Add
in A in B → out
Sample Texture 2D
in Texture in UV → RGBA, R, G, B, A

A wire passes a value from one node's output to another's input. That's it. That's the whole programming model.

Data types (the colors on wire ports)

TypeWhat it isExample
Float (1)Single numberTime, brightness
Vector 2Pair of floatsUV coordinate (u, v)

Shader Graph auto-converts where it can: dragging a Float into a Vector3 port gives (x, x, x).

Swizzling: pick components by name

The Split node breaks a Vector4 into R, G, B, A. The Combine node reassembles them.

Common trick — turn a UV into a grayscale gradient:

UV → Split → take R → feed into Base Color

This shows a horizontal black→white gradient because U goes 0→1 left to right across the surface.

Exposed properties (the Blackboard)

Anything you add to the Blackboard becomes a slider or color picker on the material inspector in the scene — without reopening the graph.

1
Click + on the Blackboard, choose Color, name it _BaseColor
2
Drag it into the canvas — it appears as a node
3
Wire it into Base Color on the Master Stack
4
Save. Now every material using this shader has a tintable color in the inspector.

Part 5 — The Nodes You'll Actually Use

UV — the coordinate system of a surface

Every point on a mesh's surface has a 2D coordinate (u, v), usually in the range 0 to 1.

  • Bottom-left of the texture = (0, 0)
  • Top-right of the texture = (1, 1)
  • The UV node gives you this coordinate for the pixel currently being shaded

Why it matters: UVs are how shaders know where they are. Almost every effect starts with "take UV, do math, make pattern."

Time — how shaders move

The Time node outputs how many seconds the game has been running.

UV.x + Time → feed into Base Color

Result: a gradient that scrolls sideways forever. Congratulations — you animated a shader without writing a single Update().

Shader animation is free. It happens on the GPU, doesn't allocate memory, doesn't call C#. Prefer it over script-driven animation whenever the effect is purely visual.

Lerp — blend between two things

Lerp(A, B, t) = A·(1−t) + B·t
  • t = 0 → output is A
  • t = 1 → output is B
  • t = 0.5 → half-and-half

The single most-used node in Shader Graph. Use it to fade between two colors, two textures, two anything.

Step and Smoothstep — turn gradients into edges

  • Step(edge, x) → returns 0 if x < edge, 1 otherwise. A hard binary cutoff.
  • Smoothstep(a, b, x) → like Step but with a smooth S-curve transition between a and b.

Mental model: Step/Smoothstep are how you turn smooth math into visible shapes. A noise pattern becomes polka dots. A gradient becomes a horizon line.

Sample Texture 2D — read an image

Sample Texture 2D
in Texture in UV (default = mesh UV) → RGBA → R, G, B, A

This is how albedo maps, normal maps, masks, and noise textures enter a shader. You hand it a texture and a UV; it returns the color at that UV.

Noise — procedural randomness

  • Simple Noise — value noise, cheap, blobby
  • Gradient Noise — Perlin-style, smooth, natural-looking
  • Voronoi — cellular, good for scales, cracks, stylized water

All take a UV and a scale, output a grayscale pattern. Feed in UV + Time to make it scroll.

Procedural noise is expensive in the fragment shader. For production VR, sample a baked noise texture instead when you can.

Fresnel Effect — the rim-light node

Outputs a bright value on edges of the object (where the surface normal faces away from the camera) and dark in the middle.

fresnel = (1 − dot(Normal, ViewDir))^Power
  • Physically motivated — real materials reflect more light at glancing angles
  • Visually: instant rim light, hologram outlines, soap bubbles, force fields

Part 6 — Hands-On: Dissolve + Rim Light

What we're building

  • An object that dissolves away controlled by a slider
  • A glowing rim edge where it's currently disappearing
  • Fully exposed to the inspector so designers can tweak it

Why this example?

It touches every concept from Parts 4–5: UV, noise, Step, Lerp, Fresnel, exposed properties, alpha clipping, and emission. Build this and you understand Shader Graph.

Step 0 — Create the graph

1
Create → Shader Graph → URP → Lit Shader Graph, name it SG_Dissolve
2
Open it. In the Graph Inspector, set Surface Type = Opaque, Alpha Clipping = ✔ enabled
3
Create a Material using this shader and assign it to a sphere in your scene

Alpha Clipping means "if alpha falls below a threshold, throw the pixel away entirely." That's how we make parts of the mesh vanish.

Step 1 — Expose properties

Add these to the Blackboard:

NameTypeDefault
_BaseColorColorwhite
_DissolveAmountFloat (slider 0–1)0
_NoiseScaleFloat10
_EdgeWidthFloat (slider 0–0.2)0.05
_EdgeColorColor (HDR)orange, intensity 3

HDR colors can go brighter than (1,1,1) — essential for glow/bloom in VR.

Step 2 — Generate the dissolve mask

1
Drop a UV node
2
Drop a Simple Noise node. Wire UV → UV input, wire _NoiseScale → Scale input
3
The node preview now shows a cloudy black-and-white pattern — that's our dissolve mask

Every pixel now has a "random" value between 0 and 1. We'll compare that value against _DissolveAmount to decide: still visible, or vanished?

Step 3 — Cut out pixels (alpha clip)

1
Drop a Step node. Edge = _DissolveAmount, In = Simple Noise output
2
Unity's Step returns 1 if In >= Edge else 0 — so this reads "keep the pixel (alpha = 1) where noise >= dissolve amount, otherwise discard it"
3
Wire Step output → Master Stack → Alpha
4
Set Alpha Clip Threshold to 0.5

Input order matters. If you swap Edge and In, the effect inverts — the object will start invisible and fill in as you raise the slider. If you see that, swap the wires.

Now push _DissolveAmount up in the inspector — the sphere dissolves in noise-shaped patches. That's already 80% of the effect.

Step 4 — Compute the glowing edge

The edge = "pixels that are about to be dissolved" = pixels whose noise value is just barely above _DissolveAmount.

1
Subtract: noise − _DissolveAmount
2
Step that result against _EdgeWidth — but inverted: we want 1 when the difference is small
3
Easiest way: use Smoothstep(0, _EdgeWidth, noise − _DissolveAmount), then One Minus the result
4
You now have a value of 1 on the dissolve edge, 0 everywhere else

Step 5 — Mix the edge color into Emission

1
Multiply the edge mask by _EdgeColor → this gives orange where the edge is, black elsewhere
2
Wire the result into Master Stack → Emission
3
Wire _BaseColor straight into Master Stack → Base Color

Save. Drag the dissolve slider — the sphere eats itself away with a glowing orange wavefront. You just shipped a shader.

Step 6 — Add a rim light (the Fresnel)

Let's make the whole object glow at its silhouette too — a classic "energy object" VR look.

1
Drop a Fresnel Effect node, Power = 3
2
Multiply it by _EdgeColor
3
Add that to the dissolve-edge emission from Step 5
4
Wire the sum into Emission

Now the object has a permanent orange rim and a brighter dissolve wavefront. Both feed into the same Emission port — no conflict.

Final graph structure

  UV ─┐
       ├─► Simple Noise ─┬─► Step(Edge=_DissolveAmount, In=noise) ─► Alpha
       │  (_NoiseScale)  │
       │                 └─► Subtract(_DissolveAmount)
       │                       └─► Smoothstep(0, _EdgeWidth) ─► OneMinus
       │                             └─► Multiply(_EdgeColor) ─┐
       │                                                       │
  Fresnel(Power=3) ─► Multiply(_EdgeColor) ─────────────── Add ─► Emission

  _BaseColor ──────────────────────────────────────────────────► Base Color

Part 7 — Debugging Shader Graphs

Rule 1: preview every node

Every node in Shader Graph has a live preview sphere at its bottom. When something looks wrong, walk backwards from the Master Stack until the preview stops matching your expectation.

Debugging rule of thumb: "The bug is in the last node where the preview still looks right → the first node where it looks wrong."

Common beginner mistakes

  • Forgot to save — Shader Graph doesn't auto-apply to materials. Ctrl+S or click Save Asset.
  • Wired a Float into an Int/Boolean — silent type coercion, unexpected results
  • Used world-space UV by mistake — effect scales with camera position. Use mesh UV (the default UV node).
  • Alpha Clipping not enabled — dissolve does nothing because Alpha is ignored on opaque shaders
  • Emission stays black — HDR intensity is 0, or Bloom is not enabled on the URP camera

Debug by wiring to Base Color

When in doubt, wire the suspect value directly into Base Color. You'll see it painted on the object:

  • Black = 0
  • White = 1
  • Red/green/blue = you wired a vector; the R/G/B channels show component values

This is the shader version of Debug.Log. Put it back when you're done.

Part 8 — VR-Specific Gotchas

VR is twice as hard on shaders

Desktop game

1920×1080 pixels × 60 fps = ~125M pixel shader invocations/sec

Quest 3 VR

2064×2208 × 2 eyes × 90 fps = ~820M invocations/sec — ~6.5× more work

A shader that runs "fine" on your desktop can tank VR framerate. Budget accordingly.

Single-Pass Instanced Rendering

Quest/Vive/Index render both eyes in one draw call to save CPU overhead. Most shaders just work, but:

  • Avoid screen-space effects based on _ScreenPosition unless you handle stereo UVs
  • Avoid sampling the camera opaque texture in Shader Graph unless you explicitly enable stereo-aware sampling
  • Test on-device early — what compiles on desktop may break on Android/Quest

Performance budget for VR shaders

Node / FeatureCostVR verdict

Overdraw — the silent VR killer

Overdraw = the same pixel being shaded multiple times because transparent objects stack up.

  • A forest of alpha-blended leaves can shade every pixel 10+ times
  • In VR, that's 10× a giant number
  • Prefer alpha clipping (opaque + discard) over alpha blending (true transparency) whenever possible
  • Use Unity's Overdraw scene view mode to visualize the damage

Our dissolve shader is alpha-clipped, not alpha-blended — which is why it's VR-safe. Good choice earlier.

Mobile VR checklist

  • Target shader complexity: Mobile variants where available
  • Keep texture samples ≤ 4 per shader on Quest
  • No dynamic branching in fragment shaders (use Lerp, not If)
  • Bake lighting whenever possible — real-time PBR + shadows is expensive
  • Profile on-device, not in the editor — desktop preview lies

The big mental model

A shader is a function from pixel coordinate to color. Everything else — textures, noise, time, fresnel, dissolve — is just a way of building that function out of smaller pieces.

Once you see every effect as "UV goes in, color comes out," Shader Graph stops being intimidating and starts being fun.
