Part I: Physics Overview

The Big Picture

Unity Physics Engine

  • PhysX by NVIDIA (built-in)
  • Simulates realistic physics automatically
  • Runs at fixed timestep (default: 50Hz)
  • Separate from rendering frame rate

The Physics Loop

Every Physics Step (50x per second):
1. Apply forces to Rigidbodies
2. Update positions/rotations
3. Check for collisions
4. Resolve collisions
5. Trigger collision/trigger events

That's why we use FixedUpdate() for physics code!

Key Components

Rigidbody

Enables physics simulation

Collider

Defines shape for collisions

Physics Material

Surface properties

Part II: Rigidbodies

The Physics Brain

What is a Rigidbody?

A component that enables physics simulation on a GameObject.

Rule: No Rigidbody = No physics simulation

Objects won't fall, collide, or respond to forces without one

Key Rigidbody Properties

PropertyWhat It Does
MassWeight in kg (affects force response)
DragAir resistance (slows linear motion)
Angular DragRotational resistance (slows spinning)
Use GravityEnable/disable gravity pull
Is KinematicControlled by scripts, not forces

Rigidbody Types

Dynamic

Default mode

Affected by forces and collisions

Use for: Balls, projectiles, physics objects

Kinematic

Is Kinematic = true

Script-controlled movement

Use for: Platforms, player controllers

Applying Forces

Rigidbody rb;

void Start() {
    rb = GetComponent<Rigidbody>();
}

void FixedUpdate() {
    // Continuous force (like a thruster)
    rb.AddForce(Vector3.forward * 10f);

    // Impulse force (like a jump)
    rb.AddForce(Vector3.up * 5f, ForceMode.Impulse);

    // Direct velocity change
    rb.velocity = new Vector3(0, 10, 0);
}

Common ForceMode Options

ModeUse Case
ForceMode.ForceContinuous force (thrusters, wind)
ForceMode.ImpulseInstant impact (explosion, jump)
ForceMode.VelocityChangeIgnore mass in calculation

Constraints

Freeze position or rotation on specific axes:

// Freeze rotation on X and Z (no tipping over)
rb.constraints = RigidbodyConstraints.FreezeRotationX |
                 RigidbodyConstraints.FreezeRotationZ;

// Freeze all rotation
rb.constraints = RigidbodyConstraints.FreezeRotation;

// Freeze Y position (can't jump)
rb.constraints = RigidbodyConstraints.FreezePositionY;

Part III: Colliders

Defining Physical Shape

What is a Collider?

A component that defines the shape for physics interactions.

Without Collider

Objects pass through each other

With Collider

Physics detects and resolves collisions

Primitive Colliders

Box Collider

Cubes, walls, floors

Fast

Sphere Collider

Balls, round objects

Fastest

Capsule Collider

Characters, pills

Fast

Best Practice: Use primitives when possible (better performance)

Mesh Colliders

Use with caution! More accurate, but expensive

  • Mesh Collider — Matches exact mesh shape
  • Much slower than primitives
  • Can't collide with other mesh colliders unless "Convex"
  • Best for: Static environment geometry

Compound Colliders

Combine multiple primitive colliders for complex shapes:

Car (GameObject)
├── Rigidbody
├── Box Collider (body)
├── WheelFL
│   └── Sphere Collider
├── WheelFR
│   └── Sphere Collider
└── ...

Better performance than one mesh collider!

Collider Properties

PropertyEffect
Is TriggerDetects overlap, doesn't block (more later)
MaterialPhysics material (friction, bounce)
CenterOffset from GameObject position
Size/RadiusDimensions of collider

Part IV: Triggers

Detection Without Collision

The Difference

Collision

Is Trigger = false

Objects block each other

Physics resolves overlap

Walls, floors, obstacles

Trigger

Is Trigger = true

Objects pass through

Detects overlap only

Detection zones, pickups

When to Use Triggers

Pickup Items

Coins, power-ups

Danger Zones

Lava, hazards

Detection Areas

Enemy sight range

Checkpoints

Level progress

Doors/Portals

Scene transitions

Goal Areas

Win conditions

Trigger Requirements

At least ONE object must have a Rigidbody

Works

Trigger + Rigidbody

Trigger + other object has Rigidbody

Doesn't Work

Two triggers, no Rigidbodies

Part V: Physics Events

Responding to Interactions

Collision Events

// Called when collision starts
void OnCollisionEnter(Collision collision) {
    Debug.Log("Hit: " + collision.gameObject.name);
}

// Called every frame while colliding
void OnCollisionStay(Collision collision) {
    // Continuous contact logic
}

// Called when collision ends
void OnCollisionExit(Collision collision) {
    Debug.Log("Stopped touching: " + collision.gameObject.name);
}

Trigger Events

// Called when entering trigger
void OnTriggerEnter(Collider other) {
    Debug.Log("Entered trigger: " + other.gameObject.name);

    if (other.CompareTag("Player")) {
        // Collect coin, activate checkpoint, etc.
    }
}

// Called every frame while inside trigger
void OnTriggerStay(Collider other) { }

// Called when exiting trigger
void OnTriggerExit(Collider other) { }

Collision vs Trigger Events

Collision Events

OnCollisionEnter(Collision c)
OnCollisionStay(Collision c)
OnCollisionExit(Collision c)

Parameter: Collision

Access contact points, impulse

Trigger Events

OnTriggerEnter(Collider c)
OnTriggerStay(Collider c)
OnTriggerExit(Collider c)

Parameter: Collider

Access other GameObject/component

Accessing Collision Data

void OnCollisionEnter(Collision collision) {
    // Get other object
    GameObject other = collision.gameObject;

    // Get collision force
    float impactForce = collision.impulse.magnitude;

    // Get contact points
    ContactPoint contact = collision.contacts[0];
    Vector3 hitPoint = contact.point;
    Vector3 hitNormal = contact.normal;

    // Get relative velocity
    Vector3 relVelocity = collision.relativeVelocity;
}

Common Pattern: Pickup

public class Coin : MonoBehaviour {
    void OnTriggerEnter(Collider other) {
        if (other.CompareTag("Player")) {
            // Add to score
            GameManager.instance.AddScore(10);

            // Play sound
            AudioSource.PlayClipAtPoint(collectSound, transform.position);

            // Destroy coin
            Destroy(gameObject);
        }
    }
}

Remember: Coin needs Is Trigger = true and Player needs Rigidbody!

Part VI: Physics Materials

Surface Properties

What are Physics Materials?

Define how surfaces interact during collisions:

  • Friction — How much surfaces resist sliding
  • Bounciness — How much energy is retained in bounce

Create: Assets → Create → Physics Material

Key Properties

PropertyRangeEffect
Dynamic Friction 0-1 Friction while moving
Static Friction 0-1 Friction when at rest
Bounciness 0-1 0 = no bounce, 1 = perfect bounce
Friction Combine Mode How to combine with other material
Bounce Combine Mode How to combine bounciness

Example Materials

Ice

Friction: 0.05

Bounce: 0.0

Rubber

Friction: 0.9

Bounce: 0.8

Concrete

Friction: 0.6

Bounce: 0.1

Applying Physics Materials

  1. Create Physics Material asset
  2. Set friction and bounciness values
  3. Drag material onto Collider component

Materials are assigned to Colliders, not Rigidbodies!

Part VII: Raycasting

Line-of-Sight Detection

What is Raycasting?

Casting an invisible ray to detect what it hits.

Use Cases

  • Check if player is grounded
  • Aim/shooting mechanics
  • Line-of-sight checks
  • Click detection

Advantages

  • Very fast
  • Precise direction
  • Controllable distance
  • No trigger zones needed

Basic Raycast

void Update() {
    // Cast ray forward from this object
    Ray ray = new Ray(transform.position, transform.forward);

    if (Physics.Raycast(ray, out RaycastHit hit, 10f)) {
        // Hit something within 10 units
        Debug.Log("Hit: " + hit.collider.gameObject.name);
        Debug.Log("Distance: " + hit.distance);
        Debug.Log("Hit point: " + hit.point);
    }
}

Simplified Syntax

// All in one line
if (Physics.Raycast(transform.position, transform.forward, out RaycastHit hit, 10f)) {
    Debug.Log("Hit: " + hit.collider.name);
}

// Check for hit without details
if (Physics.Raycast(transform.position, transform.forward, 10f)) {
    Debug.Log("Something is in front!");
}

Ground Check Example

public class PlayerController : MonoBehaviour {
    public float groundCheckDistance = 0.1f;

    bool IsGrounded() {
        // Cast ray downward from center
        Vector3 origin = transform.position;

        return Physics.Raycast(origin, Vector3.down, groundCheckDistance);
    }

    void Update() {
        if (IsGrounded() && Input.GetButtonDown("Jump")) {
            GetComponent<Rigidbody>().AddForce(Vector3.up * 5f, ForceMode.Impulse);
        }
    }
}

Visualizing Rays

void Update() {
    Vector3 origin = transform.position;
    Vector3 direction = transform.forward;
    float distance = 10f;

    // Draw ray in Scene view (only visible in editor)
    Debug.DrawRay(origin, direction * distance, Color.red);

    if (Physics.Raycast(origin, direction, distance)) {
        Debug.DrawRay(origin, direction * distance, Color.green);
    }
}

Layer Masks

Filter what the ray can hit:

public LayerMask groundLayer;

bool IsGrounded() {
    // Only hit objects on the ground layer
    return Physics.Raycast(
        transform.position,
        Vector3.down,
        groundCheckDistance,
        groundLayer
    );
}

Set layer in Inspector as a dropdown

Best Practices

Physics Code Location

FixedUpdate()

Force application

Rigidbody manipulation

Physics calculations

Update()

Input detection

Raycasting

Visual updates

Why? FixedUpdate runs at same rate as physics simulation (consistent behavior)

Performance Tips

  • Use primitive colliders when possible (box, sphere, capsule)
  • Avoid mesh colliders on moving objects
  • Simplify collision geometry (doesn't need to match visual mesh)
  • Use layers to filter what can collide
  • Set objects to static if they never move
  • Don't move static colliders at runtime (expensive recalculation)

Common Mistakes

Moving Transform Directly

// ❌ BAD (if using physics)
transform.position += Vector3.forward * speed * Time.deltaTime;

Use Rigidbody Instead

// ✓ GOOD
rb.velocity = transform.forward * speed;
// OR
rb.MovePosition(rb.position + transform.forward * speed * Time.fixedDeltaTime);

Debugging Physics

Console Logging

void OnCollisionEnter(Collision c) {
    Debug.Log("Collision!");
    Debug.Log(c.gameObject.name);
    Debug.Log(c.impulse.magnitude);
}

Visual Debugging

void OnDrawGizmos() {
    Gizmos.color = Color.yellow;
    Gizmos.DrawWireSphere(
        transform.position,
        detectionRadius
    );
}

Physics Settings

Edit → Project Settings → Physics

  • Gravity — Default: (0, -9.81, 0)
  • Fixed Timestep — How often physics updates (default: 0.02s = 50Hz)
  • Layer Collision Matrix — What layers can collide
